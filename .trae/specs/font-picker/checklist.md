# 字体选择器重构 - 验证检查清单 (checklist.md)

## 数据层验证
- [ ] `fonts.ts` 中 `FONTS.length <= 15`（当前约 100+ 条 → 精简到 ≤15）
- [ ] 每个字体条目都有非空 `displayName` 字段（中文显示名）
- [ ] 每个字体条目都有非空 `previewText` 字段（预览示例文本）
- [ ] 中文字体的 `category` 为 `chinese`，英文字体为 `english`，没有 `other` 分类下的小语种字体
- [ ] `SYSTEM_FONT` 也拥有 `displayName` 和 `previewText` 字段
- [ ] 没有重复的字体 `name` 或 `family`
- [ ] 各字体视觉风格差异明显（衬线、无衬线、毛笔、手写、等宽、装饰等都有覆盖）

## 字体加载验证
- [ ] `fontLoader.ts` 提供异步加载 API，返回 `Promise`
- [ ] 打开字体选择器下拉时，会自动触发字体预加载
- [ ] 字体加载完成后，下拉列表中的字形会刷新（不会让用户看到空白或系统默认字体占位）
- [ ] 重复打开/关闭下拉不会重复请求同一字体（有缓存机制）
- [ ] 在 DevTools Network 面板中能看到 Google Fonts 的 CSS 请求和字体文件请求

## UI 渲染验证
- [ ] 下拉列表中每一项的文字实际以对应字体渲染（目测每项字形不同）
- [ ] 中文字体项显示中文名称（如"思源黑体"而非"Noto Sans SC"）
- [ ] 中文字体项显示中文预览示例文本（如"天地玄黄 宇宙洪荒"）
- [ ] 英文/装饰字体项显示英文名称和英文预览文本
- [ ] "系统默认"选项始终位于列表顶部，有清晰的视觉标记
- [ ] 字体项高度适中（~40px），字号 ≥16px，可清晰分辨字形特征
- [ ] 下拉宽度足够（≥280px），中文名称不被截断或换行过度
- [ ] 当前选中字体有明显高亮显示

## 交互验证
- [ ] 点击"系统默认" → 编辑器恢复浏览器默认字体
- [ ] 点击某个中文字体（如"思源黑体"）→ 编辑器选中文字立即变为该字体
- [ ] 点击某个英文字体（如"Inter"）→ 编辑器选中文字立即变为该字体
- [ ] 字体选择后下拉自动关闭，无需额外操作
- [ ] 搜索框支持中文、英文关键字匹配
- [ ] 搜索后只显示匹配项，匹配范围包括字体 `name`、`displayName`、`tags`

## 构建与类型验证
- [ ] `npm run build` 成功，无 TypeScript 编译错误
- [ ] 运行时无控制台报错（console.error / console.warn 中没有字体相关错误）
- [ ] `FontData` 接口的类型定义与实际使用一致

## 性能与体验
- [ ] 首次打开下拉时，字体加载过程中浏览器不会冻结/无响应
- [ ] 第二次及以后打开下拉，字体立即可用（有缓存）
- [ ] 应用所选字体到编辑器时无明显延迟（≤1s）
